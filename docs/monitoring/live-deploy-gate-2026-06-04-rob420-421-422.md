## Validation Caveat

The standard `bash scripts/ops/prod_validate_after_change.sh` post-check failed
only in the app-log section:

- live endpoints, services, resources, certbot status, host Node policy,
  sensitive paths, scanner paths, and Kuma were green;
- the only failure was `app_error_like_lines_current=4`;
- the redacted log summary showed the same four historical PDF renderer fallback
  errors already present before deploy;
- no recent service/journal warnings were present.

This indicates a follow-up validation-harness bug: the app-log timestamp
comparison can classify historical application log lines as current when the
remote script timestamp and application log timestamp are not using the same
timezone basis. This is not evidence of a failed deploy, but it should be fixed
before relying on ROB-420 as a strict post-change gate.
